### 校验与异常处理

- 四类场景均没有 pageerror 或 requestfailed，所有记录到的 JS/CSS 返回 200；正文元素存在。直接访问、客户端导航、阻止脚本三种情况下，正文 h1 为 30px/800、下间距 48px，代码块字体 18px，两版一致。
- 原始脚本 check-pages.mjs 完成两版捕获后，最后的整个 payload 深比较失败：两目录生成的请求 key 不同。独立脚本 summarize-pages.mjs 在不修改原 payload 的情况下检查文章响应删除 content 后深度相等、错误值与数量一致、其余顶层数据深度相等；请求 key 差异单独保存。因此不能把最初脚本整体退出 1 当作页面失败，也不能宣称原始 payload 除 content 外逐字节相同。
- 原样式探针误用了不存在的 .toc-container 并返回 null；随后使用真实 .toc-sidebar 补验最终 B。启用与阻止脚本时，桌面目录均 fixed、点击后的 hash 和目标匹配，窄屏目录隐藏。初次定位断言因目标 top=-0.015625 px 的舍入误差失败，核对后采用 1 px 容差通过；仅验证锚点位置，不代表目标不被 sticky 导航遮挡。
- 已查看最终窄屏截图，正文、代码块和评论区域可见；截图检查不替代用户的宽窄屏、滚动、导航和视觉反馈验收。没有本轮 LCP、INP 或交互耗时测量，不写加载速度提升。
