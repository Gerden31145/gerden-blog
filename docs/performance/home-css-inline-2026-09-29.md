## 1. 假设与范围

首页主要内容由 SSR 输出。原始录制中入口 JS 在文字 LCP 之后完成下载，入口 CSS 则阻塞首次绘制。本实验先启用全局样式内联，再将通知动画样式移入全局 CSS，分别验证减少外部 CSS 字节与消除外部 CSS 请求的效果。

- A0：原始配置，外部入口 CSS 16,045 B。
- A1：仅增加 `features.inlineStyles: true`，仍有通知动画 CSS 512 B。
- A2：在 A1 上将 `NoticeContainer.vue` 的非 scoped 样式移入 `main.css`，首页没有外部 stylesheet 链接。
- 修改范围：`nuxt.config.ts`、`app/assets/css/main.css`、`app/components/NoticeContainer.vue`。模板、通知逻辑与 API 未改。
- 代价：HTML 增大、内联规则不能独立跨文档复用缓存；此配置也影响其他 SSR 页面。

## 9. 暖缓存实验（2026-10-06）

用户假设：外部 CSS 命中有效缓存时可避免网络下载，而内联样式会随需要重新获取的 HTML 重复传输，首次访问优势可能缩小。本轮直接比较 A0（原始外部 CSS）和 A2（最终内联版本），没有修改或重新构建业务代码。注意这里的比较对象不同于第 5 节的 A1/A2。

### 方法与缓存证据

- 复用上述两个版本保存的生产产物；脚本为 `.perf-results/home-first-screen/run-controlled-warm-css-ab-20261006-01.mjs`，结果为同目录 `controlled-warm-css-ab-20261006-01.json`。
- Node v24.18.1，Windows 10.0.19044，i9-13980HX，Chromium 153.0.8010.12。视口 1365 × 768、DPR 1、CPU 4 倍降速，CDP 网络 latency=165 ms，下载 1,012,500 B/s、上传 168,750 B/s；供电与后台负载未独立控制。
- 本轮地址为 `http://127.0.0.1:3103/`。版本按 A、B、B、A、A、B、B、A、A、B 交替，各 5 对访问。每对启动相应版本，先以非浏览器请求预热 SSR，再创建无扩展的匿名浏览器上下文。
- 启用 HTTP 缓存：第一次访问 `/?perf_visit=cold` 记录冷访问并填充缓存；关闭页面，在同一个浏览器上下文中新建标签页访问 `/?perf_visit=warm`。每次均在 load 后等待 5 秒，不交互。
- 两个 URL 查询参数只用于区分文档缓存键，不改变页面路径、正文或静态资源 URL；新标签页正常导航避免 BFCache 恢复。所有暖访问均验证 navigation.type=navigate、HTML 未来自缓存且实际传输字节大于 0。此场景代表“HTML 重新获取、静态资源可复用”，不代表所有刷新/前进后退模式。
- A0 暖访问的 CSS 在全部 5 次中都显示 `fromDiskCache=true`、CDP `encodedDataLength=0`；响应声明 `public, max-age=31536000, immutable`。A2 暖访问没有 CSS 请求。
- 两组 LCP 元素一致，均为 About me 段落。20 次页面加载均成功、无 pageerror，10 对访问全部通过缓存与导航验证。
- 本地 HTML 未启用 HTTP 压缩；原始 JSON 保存网络缓存事件、响应头、Navigation/Resource Timing。没有把离线压缩估算当作实际传输。

### 结果

| 场景 | A0 外部 CSS：LCP 中位数 / 范围 | A2 内联：LCP 中位数 / 范围 |
| --- | --- | --- |
| 首次访问，各 5 次 | 504 ms / 500–524 ms | 292 ms / 276–308 ms |
| 静态资源暖缓存，各 5 次 | 288 ms / 284–328 ms | 300 ms / 276–324 ms |

原始 LCP，按每版出现顺序：

- A0 冷：524、500、524、504、500 ms；暖：284、308、328、288、288 ms。
- A2 冷：276、288、308、304、292 ms；暖：300、284、320、276、324 ms。

首次访问中位数相差 212 ms，支持此前首访收益方向；这是本轮独立样本，不替换旧记录或累加百分比。暖缓存内联版本中位数高 12 ms，但两组范围高度重叠，不能据此宣称稳定退化或稳定提速。

每次暖访问 HTML 实际响应体：A0 为 4,693 B，A2 为 19,752 B，内联版多 15,059 B（约 14.7 KiB），原始和编码后响应体字节一致。两版均比无查询参数的历史 HTML 多 16 B，这是本次测试 URL 的序列化差异，不能与旧表混算。外部 CSS 此时没有正文网络传输。

### 决策与下一步

已验证用户提出的取舍：内联的冷访问优势在有效静态资源缓存下明显缩小，而每次重新获取 HTML 的额外字节是确定的。本轮没有证实暖缓存下哪一版稳定更快。

保留为候选，下一步先做页面/交互回归；生产压缩、其他页面和真实访问分布仍未验证。不因单次冷缓存结果直接决定全站策略，也不因暖缓存中位数高 12 ms 立即撤销实现。未来若评估只内联关键规则，需作为独立实验验证，不在本轮追加改动。
